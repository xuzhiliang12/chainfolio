# 自动发现资产

导入公开钱包地址后，Chainfolio 会在同步时自动读取原生币和代币余额，并把记录归属到负责人、手机、钱包和地址。USDT、USDC、USDG 已内置已确认的主网部署，不需要逐个钱包重复添加。

## 识别方式

- EVM 地址优先使用兼容 `alchemy_getTokenBalances` 的索引 RPC；如果 RPC 不提供该方法，且配置了 `ETHERSCAN_API_KEY`，则调用 Etherscan 的地址代币持仓接口；在支持的链上还会尝试 Blockscout 的公开地址代币余额接口；最后才使用 ERC-20 `Transfer` 日志发现代币，再读取当前余额。
- Solana 地址使用 Token Program 和 Token-2022 Program 的 `getTokenAccountsByOwner` 查询。
- 自动发现的资产标记为“自动发现”，自定义 Token 仍然可以用于补充没有被索引服务或日志识别的资产。

索引接口返回的是已建立索引的持仓，通常比逐段扫描 Transfer 日志更完整。系统不会抓取浏览器网页 HTML；如果需要核对，建议打开对应区块浏览器页面人工比对。

## 深度补全

在“手动更新”中勾选“深度补全代币”，会让 Transfer 日志后备扫描从创世区块开始，而不是只扫描最近一段历史。建议按手机或钱包分批执行，避免公共 RPC 的请求范围和频率限制。扫描范围过大时，系统会自动缩小区块窗口；如果仍达到日志/代币保护上限，会在地址行提示“代币历史扫描未完成”，此时应配置索引 API 或分批重试。
如果某条链的索引/日志扫描暂时失败，系统会保留上一次已确认的自动发现资产，并标记“上次已知”，避免一次 RPC 波动让资产从总账中消失；该链恢复后会自动用新余额替换。

## 价值计算

系统按数据可靠性选择价格：稳定币固定按 1 USD 估值，其他代币优先使用 DexScreener 报价。没有可验证报价的代币不会被删除，仍然显示数量，并在价值列显示“暂无报价”。

## RPC 配置建议

普通公共 RPC 可能限制日志查询范围。为了获得更完整、更快的 EVM 资产列表，建议在对应网络配置支持代币索引的 RPC（例如带 Token API 的自有 RPC）。可以通过环境变量调整日志发现范围：

```text
TOKEN_DISCOVERY_FULL_HISTORY=true
TOKEN_DISCOVERY_HISTORY_BLOCKS=500000
TOKEN_DISCOVERY_MAX_TOKENS=250
TOKEN_DISCOVERY_MAX_LOGS=20000
```

完整历史扫描会增加 RPC 请求量，建议只在首次盘点或需要补全历史资产时启用；日常同步保持默认的随机批次即可。

## 隐私提示

系统只需要公开地址，不需要助记词或私钥。使用第三方索引 RPC 时，地址会被发送给该服务；如需更高隐私性，请使用自建节点或可信 RPC。
